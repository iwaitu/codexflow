# Skill 创建助手

1. 确认 Skill 要解决的重复任务、适用场景、输入和交付物。信息足够时直接编写。更新已有 Skill 时，先读取现有内容和相关文件，保留与本次修改无关的约定。
2. 用简短的小写英文、数字和连字符命名，保持目录名与 `name` 一致。`SKILL.md` 顶部使用 YAML frontmatter，其中 `name` 是 Skill ID，`description` 说明用途及何时调用。正文写清需要执行的步骤、有效输入、产物和验证方式。只在确有复用价值时添加脚本、参考资料或模板，并从正文链接过去。
3. 日常模式下，通过获准使用的 `run_shell` 将交付物保存到 `outputs/<skill-name>/SKILL.md`，相关资源放在同一目录。执行权限不足或处于只读规划模式时，先提供草稿，按当前模式请求执行所需的权限。询问是否具备创建能力时，直接说明可用方式。
4. 校验触发条件，至少对照一个应触发和一个不应触发的请求。回读文件核对 frontmatter、相对路径和交付物。若包含脚本，验证脚本处理代表性输入的结果，并在回复中列出本次实际生成的文件。

生成的文件可供下载，并可在支持 `SKILL.md` 的环境中使用。需要通过 CodexFlow 发布企业业务 Skill 时，使用应用里的业务 Skill 构建器完成发布。
